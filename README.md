# 中秋文化市集保障

可复用的公共文化活动保障后台：把活动流程、容量、印章规则与家庭、导师/非遗传承人、场地、原料批次、设备检查、年龄限制一起排定，并在活动当天保证人数与物料守恒。

## 领域资料

仓库中的 `contracts/context.schema.json` 描述基础资料格式，`fixtures/context.json` 给出可公开使用的示例。代码库只负责读取与校验这些资料，业务服务可沿用相同标识和版本约定。

当前资料反映的事实包括：

- 活动包含手作、阅读、非遗和科技体验
- 面向亲子家庭
- 科普资源包免费发放并延伸到家庭

## 排定资料

`contracts/plan.schema.json` 与 `fixtures/plan.json` 描述一场活动的完整排定：

- **场地**（容量）与**人员**（导师 `mentor` / 非遗传承人 `inheritor`）
- **活动**（类别、所需确认事项、年龄限制、单人物料、设备类型、是否生成阅读/科普记录）
- **原料批次**（初始数量、单位）、**设备**与开场前的**设备检查**
- **场次**（活动 × 场地 × 人员 × 时段 × 容量 × 所用设备）
- **印章规则**（完成某类别活动满 N 次自动发放电子印章，替代纸质集章）
- **家庭与成员**（含已完成的过敏提示/影像授权/安全确认）与**结伴组**

`src.plan.load_plan` 读取并校验排定资料，引用不一致（场次指向不存在的活动、活动指向不存在的批次等）会在启动前被拒绝。

## 运行后台

`src.backend.MarketBackend` 承载活动当天的全部操作：

- **预约与结伴**：`book` / `book_group`（整组同行，名额不足整组不约）；名额受场次与场地容量双重约束，年龄限制在预约时即校验
- **扫码核销**：`check_in` 校验确认事项、年龄、设备状态并发放物料；未预约观众在名额允许时自动补建预约；重复扫码按自然键去重，不重复占名额、不重复发物料
- **完成与记录**：`complete` 生成个人阅读/科普记录（结伴不影响归属，记录始终按成员独立保存），并按印章规则自动发章
- **异常处置**：`change_venue`（临时换场，目标场地必须容纳已约人数）、`set_device_status`（停用/故障）、`swap_device`（换备用机）、`fail_session`（取消场次，已发物料按损耗或归还入账）
- **工作人员看板**：`staff_overview(at)` 实时给出各场次剩余名额与物料、停用设备、尚未完成确认事项的已约成员

### 断网补传与幂等

一切操作都是携带 `event_id` 的事件（`apply` / `apply_batch`）：

- 同一 `event_id` 只生效一次，离线终端网络恢复后整批重传不会产生重复效果
- 被拒绝的操作（名额已满、物料不足、确认事项缺失、年龄不符、设备不可用）也如实记入事件日志，附稳定的原因代码
- 把事件日志原样重放到新实例，状态完全收敛（见 `tests/test_sync.py`）

### 守恒保证

`src.reports.assert_conservation` 校验：

- 人数：每场次有效预约数不超过有效容量（场次与场地取小）
- 物料库存：每批 `初始 = 剩余 + 发放 - 归还`
- 物料去向：每批 `发放 = 归还 + 损耗 + 在参与者手中`

断网补传、重复扫码、临时换场、设备故障之后，这些守恒式必须仍然成立（测试已覆盖）。

## 赛后说明

`src.reports` 提供：

- `resource_report` —— 逐批说明资源去向（初始/发放/归还/损耗/剩余与全部流水，每条流水可追溯到预约）
- `service_report` —— 逐场次服务结果，并汇总未服务成功的明细与原因
- `family_journey` —— 家庭视角的真实参与过程还原（含被拒绝的尝试及原因、印章、个人阅读与科普记录）

```bash
python -m unittest discover -s tests   # 或 python -m pytest
```
